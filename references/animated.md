# 动态表情（透明背景 GIF）方案

静态那套在 `SKILL.md`。这篇讲动图，两者**不能混在同一套专辑里**（官方要求同套统一动/静）。

## 官方要求

| 项 | 要求 |
|---|---|
| 格式 | GIF |
| 尺寸 | 240×240 |
| 单张体积 | ≤500KB |
| 数量 | 8～24 个（与静态同规则） |
| 播放 | 须设置循环播放，节奏流畅不卡顿 |

**卡死方案上限的一条**（官方原文）：

> 仅为了满足动态要求而进行无意义的**缩放、平移、晃动、闪烁**，
> 脱离了实际含义或创意，不能通过审核。

所以「拿一张静态图程序化地缩放位移」这条最省事的路是**走不通的**，
必须是真有动作差异的多帧。这决定了整条流水线的形态。

## 绕不过去的技术约束：GIF 只有 1-bit 透明

PNG 的 alpha 是 0~255 连续值，GIF 的透明只有「是/否」两种。
每个半透明像素必须二选一，代价对称：

| 选法 | 结果 |
|---|---|
| 判为不透明 | 边缘残留原背景色 → **微信深色模式下镶一圈白边/灰边** |
| 判为透明 | 边缘变硬（锯齿），但不出异色描边 |

PS 教程里常说的「存储为 Web 所用格式 → 杂边设为白色」属于第一种：
浅色模式看着干净，深色模式每张图都带白边。**别用。**

本方案取第二种：**阈值 128 二值化 + 主体腐蚀 1px**。
腐蚀这一步的思路来自 [hackerb9/mktrans](https://github.com/hackerb9/mktrans)
（它的做法是「抗锯齿 alpha 再腐蚀半像素以避免 halo」）。
实测浅底与深底都不出 halo，代价是边缘略硬。

### PIL 的一个坑

直接 `im.convert("P")` 会**丢掉 alpha**，光设 `info["transparency"]` 没用 ——
实测输出的 GIF alpha 是 100% 不透明，透明信息全丢。必须把透明像素
`paste` 成保留的调色板索引：

```python
p = im.convert("RGB").convert("P", palette=Image.ADAPTIVE, colors=255)
p.paste(255, mask=<透明区 mask>)      # 255 是保留给透明的索引
p.info["transparency"] = 255
```

## 四步流水线

```
① 动作帧来源 → ② 逐帧抠图 → ③ 切 240×240 → ④ 合成 1-bit 透明 GIF
```

### ① 动作帧来源（三条路）

| 路径 | 做法 | 取舍 |
|---|---|---|
| **A. 图生视频 → 抽帧** | `museav gen --video --image <正面照> --duration 4` → `ffmpeg` 抽帧 | 时间连贯性由视频模型保证、动作自然、可自动化；缺点是烧 credits，逐帧抠图有帧间抖动 |
| B. AI 出多姿态帧 | 垫图分别出「动作第 1/2/3 阶段」 | 每帧独立生成，形象漂移明显，帧间会跳 |
| C. 自己画 / 实拍 | 手绘逐帧或连拍 | 质量最好，成本最高 |

A 是唯一能自动化的，默认走它。注意 Seedance **最短 4 秒**，传 3 秒会被拒。

出视频的 prompt 要点：小幅可循环动作（眨眼、挥爪、点头）、
**静态镜头**（`static camera`，镜头一动抠图就跟着漂）、主体完整在画面内、
纯色简单背景（好抠）、无文字无水印。

### ② 逐帧抠图

```bash
ffmpeg -i clip.mp4 -vf fps=6 frames/%03d.png        # 4 秒 × 6fps = 24 帧
for f in frames/*.png; do museav remove-bg "$f" --model birefnet --overwrite; done
```

`museav remove-bg` 的三个 bug 修好之后这步才可用（见 `pitfalls.md` 第十条）。
birefnet 对毛发边缘明显好于 isnet/u2net。

### ③④ 切图与合成

```bash
python3 scripts/make_gif.py <抠好的帧目录> <输出.gif> --fps 12
```

`make_gif.py` 会统一切成 240×240、二值化 alpha、腐蚀 1px，然后自适应压到 500KB：
先降色深（255→192→128→96 色），压不下去才抽帧 —— **抽帧放最后**，因为它直接损伤流畅度。

实测体积：3 帧 240×240 约 67KB，**500KB 大约能装 20 帧**。

## 哪种 IP 适合做动图

| 类型 | 适合度 | 原因 |
|---|---|---|
| **插画 / 3D 渲染型** | ✅ 适合 | 边缘干净利落，1-bit 二值化后不出毛刺 |
| **照片型（真人/真宠物）** | ❌ 不建议 | 毛发边缘是连续过渡的半透明，正好是 1-bit 透明最吃亏的地方：腐蚀会啃掉毛尖，不腐蚀就镶白边，两头都难看 |

## 成本预估（一套 8 个动图）

- 8 段 4 秒视频：8 次 `museav gen --video`
- 抽帧后约 8 × 20 = 160 帧要抠图，birefnet 单帧约 10s → 约 27 分钟
- 合成与压缩：秒级

所以动图一套的成本比静态高一个量级，**先做 1 个验证质量再批量**。

# 推广视频（1080×1920 竖版）

发朋友圈 / 视频号用，**不是平台素材字段** —— 所以可以有文字、可以写「微信」。
官方示例视频标题就是「微信气泡狗宅家篇」。而详情页横幅里出现「微信」二字会被判
「推广非自有版权的应用程序」直接驳回。**两种物料要分开准备，别拿同一张图两头用。**

## 规格（实测官方示例）

| 项 | 值 |
|---|---|
| 尺寸 | 1080 × 1920（竖屏 9:16） |
| 帧率 | 30 fps |
| 时长 | 约 20 秒（官方示例 19.7s，串 7~8 张） |
| 编码 | H.264 + AAC |
| 每张停留 | 2~3 秒 |

版式：白底 + 粉/青装饰弧 → 顶部专辑名（大）+ 形象名（小）→ 中间表情图 →
下方文字说明 → 底部引导语，全程配乐。

## 用法

```bash
scripts/make_promo.py <系列目录> \
  --footer "微信搜「<专辑名>」添加整套" \
  --music ~/.wechat-stickers/bgm/mixkit-682-儿童轻快.mp3 \
  --sec 1.8            # 张数多时压缩每张停留，19 张 × 1.8s ≈ 34s
```

文案的真源是 `album.yml` 的 `captions` 段，脚本自动读；`--captions <文件>` 只作临时覆盖。

官方要求用秒剪 APP 手工做（导入素材 → 加标题 → 逐张加文字）。
本地生成的好处是**改一个字重跑只要几秒**，多套系列不用重复劳动。

## 排版能力在 museav，不在这个脚本里

`make_promo.py` 只做表情包特有的部分：读 `album.yml` 取专辑名/形象名/文案，
再按 `表情图/` 的目录约定拼出参数。真正出视频的是 **`museav slideshow`**（v2.9.0+）：

```bash
museav slideshow ./图片目录 --title "标题" --subtitle "副标题" \
  --caption "第一张的文案" --caption "第二张的文案" \
  --footer "引导语" --music bgm.mp3 --sec 2.2 --out 成片.mp4
```

这么分是因为「图集 + 文案 + 配乐 → 竖版视频」跟表情包没关系 ——
产品图、作品集、日报都要用，放在表情包 skill 里等于把通用能力锁死在一个场景。
要改版式、加主题、换尺寸，去改 museav 的 `src/local-slideshow.ts`，不要在这里重写一套。

## 三个坑（已在 museav 里修掉，这里记着是为了别再踩）

**小图必须显式放大，而且要先裁透明留白。** PIL 的 `thumbnail`、sharp 的
`withoutEnlargement` 都只缩不放 —— 源图 240×240、目标上限设 660，它会原样贴上去，
在 1080 宽的竖屏里只占两成宽。要显式 `resize` 到 520px（约占画面 48%，对齐官方示例比例）。
另外贴纸四周常有大片透明留白，不先裁掉的话放大的是留白、主体照样小。

**配乐别直接 `-shortest`。** 配乐通常比视频长几倍，硬切会在中途断掉。要裁到视频长度并淡出：

```
-af "atrim=0:<总时长>,afade=t=in:st=0:d=1,afade=t=out:st=<总时长-1.5>:d=1.5"
```

**concat demuxer 会忽略最后一项的 `duration`。** 末页一闪而过，
只能把末页在 list 文件里多写一次。

## 配乐来源

[Mixkit Free Stock Music](https://mixkit.co/free-stock-music/)：**免费、免署名、可商用、免登录**。

直链规律：`https://assets.mixkit.co/music/<id>/<id>.mp3`

页面上的「Download Free Music」是 JS 按钮没有 href，但其
`data-download-ButtonModalUrlValue` 带着 `/free-stock-music/download/<id>/`，
请求那个地址返回的 HTML 里就有 mp3 直链。

Suno 也能做 AI 配乐，但它需要登录（Google/Discord），agent 代不了 ——
要用得本人登录后再接手。Mixkit 免登录 + 免署名，流程更干净。
