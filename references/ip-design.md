# IP 文字设计手册（照着填就能过）

素材是硬门槛，文案是软门槛 —— 但文案决定用户**搜不搜得到、发不发得动**。
全部字数上限见 `specs.md`，这里只讲怎么写。

## 1. 形象名称（≤8 汉字，5 字内最佳）

官方硬要求：无标点、无空格、**能对应到具体角色**，不能用泛称或主题风格命名。

| 写法 | 判定 |
|---|---|
| 莓啾、糯米团、豆豆猫 | ✅ 一听就是一个角色 |
| 治愈系日常、粉色少女心 | ❌ 主题风格，不是角色 |
| 小可爱、表情包君 | ❌ 泛称 |
| 莓啾! / 莓 啾 | ❌ 含标点 / 含空格 |

起名套路：**质感词 + 拟声/叠字**（莓啾、团团、咕叽）或 **材质 + 身份**（糯米猫、奶盖狗）。
同一作者不得重名，起完先在平台搜一遍。

## 2. 形象简介（≤80 汉字）

三句式，一句一件事：**它是谁 → 性格是什么 → 在做什么**。

> 莓啾是只顶着草莓蝴蝶结的短腿猫，情绪全写在脸上：一秒炸毛，一秒装乖。
> 你想说又不好说的话，让它替你说。

避免写成设定表（"身高 20cm，爱好睡觉"），也避免空话（"超级可爱的表情包"）。
最后一句最好点出**使用场景**，这句会直接影响用户要不要下载。

## 3. 专辑名称（≤8 汉字，5 字内最佳）

无标点无空格，且不与平台已有专辑重名。公式：**形象名 + 的 + 场景/情绪范围**。

> 莓啾的情绪小剧场（8 字，压线）／ 莓啾日常（4 字，最佳）

一个形象可以出多套专辑，专辑名之间要有区分度（日常篇 / 打工篇 / 过年篇）。

## 4. 情绪矩阵（静态 8~9 张的标准配置）

选题原则：**覆盖聊天里真的会发的场景**，且两两画面差异足够大（相似构图是最高频拒因）。

关键一点是**每个选题都要绑一个姿势或视角**，不能只写情绪。用垫图出图时形象会保持一致，
代价是姿势也跟着一致 —— 8 张全是正面坐姿、只有表情在变，机检直接判「构图偏接近」。
默认这 9 个已经把姿势差异写进去了：

| # | 情绪 + 姿势/视角 | 聊天场景 | 建议含义词 |
|---|---|---|---|
| 1 | 开心大笑**并举起双手** | 附和、庆祝 | 开心 |
| 2 | 委屈流泪**侧身低头** | 求安慰、卖乖 | 委屈 |
| 3 | 好困打哈欠**躺着伸懒腰** | 深夜聊天、想睡 | 好困 |
| 4 | 生气跺脚**站立** | 假装生气 | 生气 |
| 5 | 疑问歪头**只露上半身特写** | 没听懂、问细节 | 疑问 |
| 6 | 收到点头**站直敬礼** | 回应任务 | 收到 |
| 7 | 拜托合手**跪坐仰视** | 求人帮忙 | 拜托 |
| 8 | 无语摊手**背对回头** | 吐槽、认命 | 无语 |
| 9 | 害羞捂脸**蹲下** | 被夸、示好 | 害羞 |

要换题材就整组换（打工篇：加班、摸鱼、开会、下班、发薪、被催、请假、汇报、摆烂），
但别混搭 —— 同一套的风格与题材范围要统一，**姿势差异照样要带上**。

## 5. 含义词（每张 ≤4 汉字，同套内不得重复）

**含义词是搜索词，不是台词。** 用户在表情面板里输入的是「委屈」，不是「555…我没事」。

| 画面里的字（可以长） | 含义词（≤4 字、普通话、无标点） |
|---|---|
| 什么？！ | 什么 |
| 555…我没事 | 我没事 |
| 在干嘛呀？ | 在干嘛 |
| 关我屁事 | 不关我事 |
| 拜托拜托～ | 拜托 |

三个铁律：① 不超 4 字；② 同套不重复（重复会被打回）；③ 用普通话，不用方言/网络缩写
（方言必须用时写汉字音译）。**不要带标点和语气符号**（～、…、！）。

## 6. 版权信息（≤10 汉字）

已注册版权填注册信息，没注册就填设计师名或工作室名，尽量短。个人投稿直接填笔名即可。

## 7. 赞赏引导语（5~15 汉字）

与形象强绑定 + 一个软请求。官方示例：「气泡狗如此可爱，发个赞赏可好？」

> 莓啾今天很努力，赏它一颗草莓？（15 字，压线）

## 8. 填完就机检

文案写进 `album.yml`（模板在 `templates/album.yml`），然后：

```bash
python3 scripts/check_assets.py <素材目录> --copy album.yml
```

脚本会校验：每个字段字数、名称含标点/空格、含义词条数是否与表情图张数一一对应、
含义词是否超 4 字或重复、赞赏引导语是否落在 5~15 字区间。
